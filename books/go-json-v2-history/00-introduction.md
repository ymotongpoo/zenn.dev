Goで次のコードを書くと、`Name` フィールドには `gopher` が入ります。

```go
type User struct {
	Name string `json:"name"`
}

var u User
json.Unmarshal([]byte(`{"NAME":"gopher"}`), &u)
```

JSONのキーは `NAME`、構造体タグで指定した名前は `name` ですが、それでもマッチします。`nAmE` でも `Name` でも同じです。これを初めて経験ときは驚きますし、私も違和感がありました。しかしこれはバグではありません。`encoding/json` のドキュメントに、大文字小文字を区別しないマッチを行うと明記されている仕様です。

そして仕様であるからこそ、14年間もの間、挙動が変更されませんでした。

2016年に「これはおかしいのではないか」という [issue](https://github.com/golang/go/issues/14750) が立ち、セキュリティ上の懸念も指摘され、実際に[修正パッチ](https://go-review.googlesource.com/c/go/+/224079)を書いた人までいました。それでも直りませんでした。Go 1.27で `encoding/json/v2` が正式に入るまで、この挙動は一度も変わっていません。

なぜ修正されなかったのでしょうか。そして、なぜ修正ではなく、別の名前で作り直すことになったのでしょうか。そして14年かけて、どういう形に着地したのでしょうか。

その答えの一部は、標準ライブラリの外にあります。[`goccy/go-json`](https://github.com/goccy/go-json) や [`bytedance/sonic`](https://github.com/bytedance/sonic) といった高速なJSONライブラリ群は、v1が修正できなかったからこそ生まれました。そして速くするために、v1の欠陥まで忠実に写し取るという、妙な仕事を引き受けることになります。その忠実さが、実際にバグを生みました。

## 前提知識

必要な前提は次の3点です。

* `encoding/json` はGo 1.0（2012年）からある標準パッケージで、`Marshal` でGoの値をJSONに、`Unmarshal` でJSONをGoの値に変換する。
* Goには後方互換性保証がある。Go 1の仕様に沿って書かれたプログラムは、その後のGoでもコンパイルでき、同じように動き続ける。
* `GOEXPERIMENT` はビルド時に指定する環境変数で、まだ正式でない機能を有効化したり、新しくなったデフォルトを元に戻したりするために使う。実行時に効く `GODEBUG` とは別物である。
